# Matriz de pruebas S11

Cada fila es un caso distinto. Las aserciones de una misma fila pertenecen a ese caso y no se cuentan como casos separados.

Todos los casos llaman `POST /api/test/reset` antes de ejecutarse. Así parten del menú inicial y de cero pedidos.

| ID | Operación | Riesgo | Precondiciones | Datos | Resultado esperado | Aserciones | Limpieza |
| --- | --- | --- | --- | --- | --- | --- | --- |
| S11-01 | POST /api/pedidos | Aceptar un pedido incorrecto o no guardarlo | Datos reiniciados. Token de ana-laboratorio | 1 Café Americano | 201. Pedido confirmado, total 3500 centavos, dueño ana-laboratorio | El código HTTP es 201. El id es numérico, el código es ORD más ese id, el estado es confirmed, el total es 3500 y el dueño es el usuario autorizado. Luego se consulta la lista y el pedido sí quedó guardado | Reset al inicio. No depende de otro caso |
| S11-02 | GET /api/pedidos/{id} y GET /api/products | El pedido se crea, pero el total o el stock no cambian como deberían | Datos reiniciados. Se crea un pedido de 1 Café Americano y 2 Cappuccino | Pedido recién creado por ana-laboratorio | El pedido guardado suma 12500 centavos y el stock baja: Americano 19, Cappuccino 13 | El GET del pedido devuelve 200, el mismo id, total 12500 y dos productos. El menú queda con stock 19 y 13 | Reset al inicio. El pedido se crea en la preparación de este caso |
| S11-03 | POST /api/pedidos | Aceptar una cantidad que no tiene sentido | Datos reiniciados. Token de ana-laboratorio | productId 1 y quantity 0 | 400. No se guarda ningún pedido | El mensaje es que la cantidad debe ser un entero mayor que cero. La lista de pedidos sigue vacía | Reset al inicio |
| S11-04 | POST /api/pedidos | Crear un pedido sin los datos obligatorios | Datos reiniciados. Token de ana-laboratorio | Cuerpo vacío {} | 400. No se guarda ningún pedido | El mensaje es que el pedido no puede estar vacío. La lista de pedidos sigue vacía | Reset al inicio |
| S11-05 | POST /api/pedidos | Crear un pedido sin autenticación | Datos reiniciados. No se envía Authorization | 1 Café Americano, sin token | 401. No se guarda ningún pedido | El mensaje indica que falta el token. La lista de pedidos sigue vacía | Reset al inicio |
| S11-06 | POST /api/pedidos | Aceptar un token que no existe | Datos reiniciados. Token lab-token-invalido | 1 Café Americano | 401. No se guarda ningún pedido | El mensaje indica que el token no es válido. La lista de pedidos sigue vacía | Reset al inicio |
| S11-07 | GET /api/pedidos/{id} | Un usuario vea el pedido de otra persona | Datos reiniciados. Ana crea un pedido. Luis tiene un token válido, pero no es el dueño | Token de luis-laboratorio sobre el pedido de Ana | 403. El pedido sigue existiendo para Ana | El mensaje dice que no puede consultar un pedido de otro usuario. Con el token de Ana el mismo pedido responde 200 | Reset al inicio. El pedido se crea en la preparación de este caso |
| S11-08 | GET /api/pedidos/99999 | Confundir un id que no existe con un error de permiso | Datos reiniciados. Token de ana-laboratorio | Id 99999 | 404 | El mensaje dice que no se encontró el pedido | Reset al inicio |
| S11-09 | GET /api/productos | Devolver una página incompleta o un total incorrecto | Menú inicial de 4 productos | page 1 y limit 2. También se revisan la página 2 y la página 3 | 200. La primera página trae 2 productos, total 4. La página 3 viene vacía sin perder el total | data tiene 2 elementos, page 1, limit 2, total 4 y count 2. La página 2 trae Latte y Pastel. La página 3 trae count 0 y total 4 | No modifica pedidos. Reset al inicio para asegurar el menú |
| S11-10 | GET /api/productos | Aceptar una página o un límite inválidos | Ninguna dependencia de pedidos | page 0. También limit 0 y limit 21 | 400 en los tres intentos | page 0 pide un entero mayor o igual que 1. limit 0 y limit 21 piden un entero entre 1 y 20 | No escribe datos |
| S11-11 | PUT /api/pedidos/{id}/estado | Una repetición cree otro pedido, cambie el total o vuelva a descontar stock | Datos reiniciados. Ana crea 1 Café Americano | Se envía dos veces status listo | Las dos respuestas quedan en listo. El efecto final no cambia después de la segunda | Tras la segunda llamada, el pedido sigue en listo, el total sigue en 3500, el stock del Americano sigue en 19 y existe un solo pedido | Reset al inicio. El pedido se crea en la preparación de este caso |
| S11-12 | GET /api/pedidos/{id}, GET /api/productos y GET sin token | La respuesta no cumple el contrato, por ejemplo un entero que llega como texto | Datos reiniciados. Ana crea 1 Café Americano | Pedido propio y una consulta sin token | 200 con la forma del pedido y de la página. 401 con la forma de error | El pedido trae las claves del contrato y quantity es un entero. La página trae data, page, limit, total y count. El error solo trae el campo error, de tipo texto | Reset al inicio. El pedido se crea en la preparación de este caso |
